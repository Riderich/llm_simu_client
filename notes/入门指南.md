## 一、项目是什么？解决什么问题？

### 核心问题

我们正在训练一个能**真实模拟心理咨询来访者阻抗行为**的 LLM。

**为什么这个问题有价值？**

- 心理咨询培训中，实习咨询师需要大量练习，但真实病人有限，"模拟病人"需求巨大
- 现有 LLM 天然倾向于"配合"和"顺从"，无法真实还原来访者的阻抗心理
- 阻抗行为（如质疑、逃避、否认）需要内在动机驱动，不是靠表面话术能模仿的

**阻抗（Resistance）是什么？** 来访者在心理咨询中不愿配合治疗的言语行为，如质疑咨询师、转移话题、找借口逃避，是真实咨询中的常见现象。

### 整体训练链路

```
数据集（多来源）
  → 细粒度行为标注（A1-D2 / CBS2-8）
  → Background Profile 提取（来访者背景档案）
  → Inner Monologue 生成（内心独白，CoT）
  → SFT 监督微调
  → DPO 偏好优化（针对 hard case）
```

简单理解：我们先给模型准备"真实来访者的内心活动数据"，再用这些数据训练模型，让它在回复前先"想一想"，而不是直接输出顺从的回复。

## 三、核心概念速成

### 3.1 行为分类体系（14 类）

我们对每一条来访者发言（utterance）打一个标签，共 14 类：

**阻抗侧（A-D 类，11 子类）** — 来自 RECAP/PsyFIRE 框架

| 大类 | 子类 | 含义 | 例句 |
|------|------|------|------|
| A 争辩 | A1 挑战 | 质疑咨询师信息准确性 | "Are you sure about that?" |
| A 争辩 | A2 贬低 | 否定咨询师权威 | "You don't know what it's like." |
| B 否认 | B1-B7 | 责怪他人、找借口、最小化问题... | 详见行为空间框架.md |
| C 回避 | C1 最小回应 | 极短应答结束话题 | "Yeah." / "I don't know." |
| C 回避 | C2-C4 | 界限设定、转移话题、表面顺从 | — |
| D 忽视 | D1-D2 | 走神、引入无关叙述 | — |

**非阻抗侧（E 类，CBS2-8 子类）** — 来自 CBS 框架

| CBS 标签 | 含义 | 参与深度 |
|---------|------|---------|
| CBS2 认同 | 接受咨询师观点 | 低 |
| CBS3 请求 | 主动提问 | 中 |
| CBS4 叙述 | 叙述事实经过 | 低 |
| CBS5 认知探索 | 探索自身想法 | 高 |
| CBS6 情感探索 | 探索情感深度 | 高 |
| CBS7 领悟 | 表达洞见 | 高 |
| CBS8 改变 | 报告/承诺改变 | 高 |

> **重要**：实际标注输出为 CBS2-8 而非 E1/E2/E3，E1/E2/E3 是事后分析用的聚合分组。

### 3.2 数据集概况

| 数据集 | 语言 | 来源 | 特点 | 阻抗率 |
|--------|------|------|------|--------|
| **ESConv** | EN | 众包模拟咨询 | 情绪化，A2（贬低）为主 | 29% |
| **MESC** | EN | TV 真实治疗录像 | 理性克制，A1+C1 为主 | 8.7% |
| **AnnoMI** | EN | YouTube 真实咨询 | 高质量 MI 演示，C1 为主 | — |
| **RECAP** | ZH | 真实中文咨询 | 分布最均匀，覆盖最全 | — |
| **ExTES** | EN | LLM 合成 | 阻抗比例仅 6%，辅助语料 | 6% |

数据集本地路径均在 `workspace/dataset/`，详细信息见 [`数据集.md`](数据集.md)。

### 3.3 Background Profile

对每个来访者，我们用 LLM 从对话全文中提取一份结构化"背景档案"，包含：
- 基本背景信息（职业、家庭等）
- 对问题的自我认知
- 阻抗驱动因素
- 核心心理矛盾

Profile 存储在 `workspace/results/profiles/`，格式为 JSON。

### 3.4 Inner Monologue（内心独白）

模型在生成回复之前，先生成一段"内心独白"（Chain-of-Thought），格式为：

```xml
<internal>
[来访者在听到咨询师发言后、说出回复前的内心活动]
</internal>
[最终回复]
```

这是整个训练链路的核心，让模型有"动机"而非机械模仿。
内心独白按行为类别使用 5 套独立 Prompt 模板（见 [`技术方案演进.md`](技术方案演进.md) 第八节）。

## 四、环境配置

### 4.1 激活 Python 环境

```bash
# 方式一：使用封装脚本（推荐）
source workspace/scripts/activate_recap_vllm.sh

# 方式二：手动激活 conda 环境
conda activate recap_vllm
```

### 4.2 配置 API Key

```bash
# 复制模板（如果 .env 不存在）
cp workspace/.env.example workspace/.env

# 编辑填入你的 key
vim workspace/.env
```

`.env` 文件内容格式：
```bash
OPENAI_API_KEY=sk-xxx          # DeepSeek API Key
QWEN_API_KEY=sk-xxx            # 阿里云 DashScope Key（用于 Qwen）
DASHSCOPE_API_KEY=sk-xxx       # 同上，部分脚本用这个名
```

> API Key 不要提交到 git，`.env` 已在 `.gitignore` 中。

### 4.3 确认 GPU

```bash
nvidia-smi                  # 查看可用 GPU
# 本地模型任务通常使用 GPU 4（--gpu 4 参数）
```

## 五、核心任务操作指南

### 5.1 任务一：二分类阻抗检测（本地 RECAP 模型）

将每条 utterance 分类为"阻抗"或"合作"，使用本地 GPU 运行。

```bash
cd workspace
python scripts/run_binary_resistance_classification.py \
    --data-format annomi \
    --input data/processed/AnnoMI-full.json \
    --output results/labeled/annomi_binary.json \
    --gpu 4
```

`--data-format` 可选值：`annomi` / `extes`

### 5.2 任务二：细粒度阻抗标注（A1-D2，本地模型）

```bash
cd workspace
# AnnoMI
python scripts/annomi_resistance_fine.py

# ESConv
python scripts/esconv_resistance_fine.py

# MESC
python scripts/mesc_resistance_fine.py
```

后台长时间运行推荐用 nohup：

```bash
nohup /path/to/recap_vllm/bin/python -u scripts/annomi_resistance_fine.py \
    > results/logs/profiles/annomi_resistance_nohup.log 2>&1 &

# 查看进度
tail -f workspace/results/logs/profiles/annomi_resistance_nohup.log
```

> **注意**：不要用 `conda run -n xxx python ... &`，nohup 中不稳定。
> 应直接指定 conda 环境的 Python 二进制路径（见 [`技术方案演进.md`](技术方案演进.md) 第三节）。

### 5.3 任务三：细粒度合作标注（CBS2-8，Qwen API）

```bash
cd workspace
DASHSCOPE_API_KEY=sk-xxx python scripts/annomi_coop_cbs.py
# 或将 key 写入 .env 后直接运行
python scripts/annomi_coop_cbs.py
```

同理有 `esconv_coop_cbs.py` / `mesc_coop_cbs.py` / `recap_coop_cbs.py`。

### 5.4 任务四：Background Profile 提取（API LLM）

```bash
cd workspace
python scripts/run_profile_extraction.py \
    --input  data/processed/AnnoMI-full.json \
    --output results/profiles/annomi_profiles_full.json \
    --data-format annomi
```

`--data-format` 可选值：`annomi` / `esconv` / `mesc` / `recap`

**支持断点续跑**：

```bash
# 从上次中断处继续
python scripts/run_profile_extraction.py ... --resume

# 仅重跑失败的样本
python scripts/run_profile_extraction.py ... --retry-failed
```

### 5.5 任务五：Inner Monologue 生成

```bash
cd workspace
python scripts/generate_recap_inner_monologue.py
```

评估生成质量：

```bash
python scripts/evaluate_inner_monologue.py
```

### 5.6 任务六：组装 SFT 训练数据

```bash
cd workspace
python scripts/prepare_sft_data.py
```

输出格式为 Alpaca / DPO JSON，可直接用于 LLaMA-Factory 训练。

## 八、常见问题 & 注意事项

### Q1：运行脚本时 API 限流怎么办？

脚本内置了指数退避重试机制，一般会自动处理。如果确实跑不下去，先 Ctrl+C 停止，再用 `--resume` 从断点继续。

### Q2：跑了一半的任务如何恢复？

所有长时间任务都支持 `--resume`（跳过已成功样本）和 `--retry-failed`（重跑失败样本）。

### Q3：模型输出格式乱了怎么办？

常见问题：输出带 `#注释`、带 `()` 说明、带中文冒号解释。
后处理清洗策略见 [`技术方案演进.md`](技术方案演进.md) 第二节。

### Q4：本地模型跑在哪块 GPU 上？

通常使用 GPU 4（`--gpu 4`），避免和其他人的任务冲突。
运行前用 `nvidia-smi` 确认 GPU 是否空闲。

### Q5：vLLM 还是 Transformers？

对于需要精确控制 GPU 的任务，使用 **Transformers**。
vLLM 0.6.3 存在 `multiproc_gpu_executor` 忽略 `CUDA_VISIBLE_DEVICES` 的 bug（见 [`技术方案演进.md`](技术方案演进.md) 第四节）。

### Q6：代码里的 `archive/` 文件夹是什么？

`workspace/scripts/archive/` 存放**已完成的一次性脚本**，不再维护，仅供参考。

### Q7：B6 和 B7 怎么区分？

- **B6 Reluctance**：「我不确定是否愿意」（有犹豫空间）
- **B7 Unwillingness**：「我确定不愿意」（明确拒绝）

更多边界案例见 [`行为空间框架.md`](行为空间框架.md) 第五节。
