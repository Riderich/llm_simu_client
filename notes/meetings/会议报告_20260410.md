## 三、Background Profile 设计思路

### 3.1 为什么需要 Profile？

当前 Inner Monologue（内心独白）生成面临的核心问题：

**每条 utterance 孤立生成，没有人物一致性。**

即使在同一个 COT 链条里，生成出的"内心活动"可能和来访者的实际背景矛盾——模型不知道这个人是谁、他为什么在这里、他真正在乎什么。

Profile 的作用是给每场对话建立一个**"角色锚点"**：

```
来访者是谁？（background）
他如何看待自己的问题？（self_view_of_problem）
是什么让他抗拒改变？（resistance_drivers）
他内心的矛盾张力在哪里？（ambivalence）
他最在乎什么、最不愿失去什么？（values_and_stakes）
哪些关键事实支撑上述判断？（key_facts）
```

这六个字段在 COT 生成时作为**系统级上下文**注入，保证内心独白不会出现"人格漂移"。

---

### 3.2 理论依据

Profile 的六个字段来源于两个理论框架的融合：

#### 框架一：4Ps 临床案例概念化（4Ps Case Formulation）

临床心理学中的标准评估框架，从四个维度理解来访者：

| 维度 | 英文 | 含义 | 对应 Profile 字段 |
|------|------|------|-----------------|
| 素因 | Predisposing | 使人脆弱的长期因素（性格、成长经历）| `background` |
| 诱因 | Precipitating | 触发当前问题的近期事件 | `key_facts` |
| 维持因素 | Perpetuating | 维持问题持续的机制 | `resistance_drivers` |
| 保护因素 | Protective | 阻止情况恶化的资源与优势 | `values_and_stakes` |

4Ps 框架保证 Profile 覆盖了**为什么这个人会在这里、以及为什么问题没有被解决**。

#### 框架二：动机访谈（MI）的矛盾心理理论

MI 的核心概念是来访者对改变持有**矛盾心理（Ambivalence）**：

- **Change Talk（改变话语）**：来访者表达出的想改变的理由、意愿
- **Sustain Talk（维持话语）**：来访者表达出的不想改变的理由、阻抗

`ambivalence.for_change` 和 `ambivalence.against_change` 直接对应这两个方向，使 Inner Monologue 的生成可以从"矛盾张力"出发，产出更具心理真实感的内心活动，而非机械的拒绝或配合。

---

### 3.3 字段设计决策

| 字段 | 类型 | 设计理由 |
|------|------|---------|
| `background` | string | 1-3 句，给模型提供人物基础上下文（不要过长，过长会被忽略）|
| `self_view_of_problem` | string | 关键字段——用**来访者自己的语言**描述问题，而非临床视角。防止 COT 生成时模型"治愈了"来访者 |
| `resistance_drivers` | list | 列表结构，方便 COT 生成时逐条引用；每条须有对话依据 |
| `ambivalence` | dict{for, against} | 直接对应 MI 的 change/sustain talk；分拆成两个子字段让 COT 生成可以分别"激活"一侧 |
| `values_and_stakes` | list | "他最不愿失去什么"——这是阻抗背后的驱动力，也是咨询师找突破口的切入点 |
| `key_facts` | list | 原始粒度事实（数字、事件、习惯），防止整体概括掩盖细节 |
| 字段名统一英文 | — | 中英文数据混合时字段名保持一致；字段值保留原始语言（英文/中文）|

## 四、Prompt 设计思路

### 4.1 版本演进

| 版本 | 核心策略 | 问题 |
|------|---------|------|
| v1（strict/null 版） | "证据不足则返回 null" | MESC（影视片段，背景信息少）产生大量 null 字段，Profile 残缺，不可用于模拟 |
| **v2（no-null/inferred 版）** | "证据不足则推断，推断内容加 `(inferred)` 标注" | 当前版本 |

### 4.2 v2 的核心设计原则

**原则一：Profile 的目的决定 null 不可接受**

Profile 是用来"扮演"的，字段缺失等于角色信息缺失。一个 `ambivalence.for_change = null` 的 Profile 在 COT 生成时等价于"这个人对改变毫无欲望"——这在大多数情况下并不准确，只是对话中没有明说。

**原则二：推断必须有标注，保留下游过滤空间**

允许推断不等于允许幻觉。所有基于推断（而非直接对话证据）的内容统一加 `(inferred)` 前缀：

```json
{
  "background": "(inferred) A young woman in a romantic relationship experiencing distress...",
  "ambivalence": {
    "for_change": "She came to the therapy session despite wanting to cancel.",
    "against_change": "(inferred) She may be protecting her relationship with Andrew..."
  }
}
```

这样：
- 直接证据和推断内容可通过程序区分
- 后续可对 `(inferred)` 字段做置信度加权，或在训练时降权
- 人工审核时可以快速定位"需要验证的字段"

**原则三：System Prompt 层面传递目标，User Prompt 层面传递约束**

System Prompt 定义任务定位："帮助模型扮演来访者，完整 profile 永远优于残缺 profile"。  
User Prompt 传递具体规则：优先直接证据，缺证据时推断 + 标注，绝不返回 null。

两层分工避免 LLM 把 System 的"完整"目标和 User 的"忠于事实"约束理解为矛盾。

### 4.3 数据集适配

| 数据集 | 语言 | Prompt 版本 | 额外上下文注入 |
|--------|------|------------|--------------|
| AnnoMI | 英文 | EN v2 | 无（对话质量高，上下文充足）|
| ESConv | 英文 | EN v2 | 来访者情境陈述（`situation` 字段）+ 行为标注摘要（utterance 级别标签）|
| MESC | 英文 | EN v2 | 来访者情境陈述 + 行为标注摘要 |
| RECAP | 中文 | ZH v2 | 无（对话为中文，直接使用中文 Prompt）|

ESConv / MESC 额外注入的**行为标注摘要**格式示例：

```
--- BEHAVIORAL ANNOTATIONS ---
The following client utterances were labeled in this conversation:
  [RESISTANCE] 争辩-贬低 — "I do, but often they are not going to..."
  [COOPERATION] CBS6-情感探索 — "I am having a lot of anxiety about..."
```

这使模型在提取 `resistance_drivers` 时有更准确的"事实锚点"，而非纯凭语义理解。

|------|----------------------|------------------------|

| `resistance_drivers` | 以现实压力/认知偏差为主 | 以关系张力/情感阻抗为主 |
| `key_facts` | 具体行为、数字充足 | 叙事性强，数字细节少 |

### 6.2 COT Pipeline 设计要点（预研）

COT 数据构建的逻辑链条：

```
对话 transcript
  + Background Profile（来访者角色锚点）
  + 当前 utterance 的阻抗/合作标签
  → [LLM 生成] Inner Monologue（内心独白）
  → 最终 utterance 回复

SFT 训练对：
  Input:  [系统 Prompt(Profile)] + [对话上下文] + [咨询师最新发言]
  Output: <internal>内心独白</internal>\n来访者回复
```

Profile 对 COT 的具体作用：
- `self_view_of_problem` → 约束内心独白对问题的定性
- `ambivalence` → 提供内心"矛盾张力"的两端
- `resistance_drivers` → 激活对应阻抗类型的心理动机
- `values_and_stakes` → 为回避/保护行为提供动机锚点
