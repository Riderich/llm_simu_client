## 一、Inner Monologue 生成方案演进

### 1.1 初始方案（V1.0）
**问题**：
- 第三人称分析视角（"患者可能会感到..."）
- 缺乏患者背景设定，导致角色出戏
- 模型容易切换为咨询师角色

**结果**：评估得分低，存在"治愈幻觉"

### 1.2 Prompt 2.0（当前方案）
**核心改进**：
- **第一人称沉浸**："You ARE the patient"
- **动态 Persona 提取**：从对话中提取患者背景设定
- **5套专属模板**：
  - Active Defense：争辩类阻抗
  - Evasion：回避类阻抗
  - Vulnerability：脆弱/情感探索
  - Simple Agreement：简单认同
  - Insight：领悟与改变

**结果**：平均分 4.30/5.0，角色一致性显著提升

### 1.3 未来方向
- **动态推理链条**：根据信息充分度自适应调整推理长度
- **GRPO强化学习**：对推理链长度进行奖励/惩罚

## 二、标注 Pipeline 演进

### 2.1 初期设想
- 纯人工标注 6,000+ 条数据
- 预计两周完成

### 2.2 优化方案（实际执行）
- **大模型自动标注** → **人工抽样审核** → **Ground Truth**
- RECAP 模型辅助（获取中）
- 多层后处理清洗解决格式问题

**实际结果**：
- ESConv/MESC：100%自动标注准确率
- 质量修复：43条(#注释) + 111条(无效组合) + 85条(格式问题)

### 2.3 关键经验
| 问题 | 解决方案 |
|------|---------|
| 模型输出带#注释 | `split('#')[0].strip()` |
| 模型输出带()代码 | `split('(')[0].strip()` |
| 模型输出无效组合 | 官方prompt重跑 + 子类别反推 |
| 模型输出中文冒号解释 | `split('：')[0].strip()` |

## 三、并行处理架构设计

### 3.1 方案选择
**错误方式**：
```bash
conda run -n py10 python script.py &  # ❌ conda run 在 nohup 中不稳定
```

**正确方式**：
```bash
nohup /path/to/py10/bin/python -u script.py > log.log 2>&1 &  # ✅ 直接使用 Python 二进制
```

### 3.2 多线程架构
```python
with ThreadPoolExecutor(max_workers=4) as executor:
    futures = {executor.submit(process, case): idx for idx, case in enumerate(cases)}
```

**效果**：4 workers 吞吐量提升约 3 倍

### 3.3 容错与断点续跑
**三层保障**：
1. `--resume`：跳过已成功样本
2. `--retry-failed`：仅重跑失败样本
3. `--max-retries N`：指数退避重试

**增量保存**：
```python
if processed_count % save_every == 0:
    save_checkpoint(data, output)
```

## 四、模型选型经验

### 4.1 标注任务
| 模型 | 用途 | 优点 | 缺点 |
|------|------|------|------|
| `qwen3.5-flash` | 大批量初筛 | 便宜快速 | token配额易耗尽 |
| `qwen3.5-plus` | 边界case | 质量高、稳定 | 成本较高 |
| `qwen3.5-plus-2026-02-15` | 失败样本重跑 | 最新版本 | API可能不稳定 |

**实战策略**：
- 第一轮：`qwen3.5-flash`（快速筛选）
- 第二轮：`qwen3.5-plus` + `--retry-failed`（质量保证）

### 4.2 本地模型部署
- **Transformers**：稳定，支持指定GPU，适合批量推理
- **vLLM**：速度快，但存在 GPU 设备映射问题（multiproc_gpu_executor 忽略 CUDA_VISIBLE_DEVICES）

**结论**：对于需要精确控制 GPU 的任务，优先使用 Transformers

## 五、数据结构设计决策

### 5.1 RECAP 数据格式
```json
{
  "dialogue": [
    {"role": "counselor", "content": "..."},
    {"role": "client", "content": "目标发言"}
  ],
  "target_utterance": "目标发言",
  "binary_label": "resistance",
  "label": "否认问题",
  "mapped_category": "B2",
  "e_subtype": "E2"
}
```

**为什么 dialogue 包含 target_utterance？**
- Inner Monologue 生成需要完整对话作为输入
- 单独保留 target_utterance 是为了训练时明确监督目标

## 六、失败案例与教训

### 6.1 模型输出格式失控
**问题**：微调模型输出了训练数据中的噪声格式
**教训**：需要多层后处理清洗，不能假设模型严格遵循指令

### 6.2 vLLM GPU 映射问题
**问题**：vLLM 0.6.3 的 multiproc_gpu_executor 忽略 CUDA_VISIBLE_DEVICES
**解决**：改用 Transformers 或等待 vLLM 更新

### 6.3 短句幻觉问题
**问题**：模型为"Hi"、"Yeah"等短句生造内心活动
**解决**：增加长度阈值过滤（<4个单词且无阻抗属性则跳过）

## 八、Inner Monologue Prompt 体系（Prompt 2.0）

> 整合自原 `Inner_Monologue技术文档.md` + `Inner_Monologue中文提示词.md`（已归档）

### 8.1 模板选择逻辑

按行为类别路由到 5 个独立模板，避免"大锅饭"导致语气矛盾：

```python
def select_template(case):
    parent   = case["resistance_label"]["parent"]    # A/B/C/D/E
    category = case["resistance_label"]["category"]  # Exploratory/Cooperative/Resolution

    if parent in ("A", "B"):   return PROMPT_ACTIVE_DEFENSE   # 主动防御
    if parent in ("C", "D"):   return PROMPT_EVASION           # 回避脱离
    if category == "Exploratory": return PROMPT_VULNERABILITY  # 脆弱探索 (CBS5/6)
    if category == "Cooperative": return PROMPT_SIMPLE_AGREEMENT # 简单顺从 (CBS2/3/4)
    if category == "Resolution":  return PROMPT_INSIGHT        # 领悟决断 (CBS7/8)
    return PROMPT_SIMPLE_AGREEMENT  # Fallback
```

所有模板统一注入行为子类型：`[Behavior Subtype]: {behavior_subtype}`

### 8.2 英文模板

**PROMPT_ACTIVE_DEFENSE（A1-A2, B1-B7）**
```
# Role
You ARE the patient. You are sitting in the therapy room.
You are not an AI, not an observer, and not a writer.

# Task
The dialogue is COMPLETE — it includes your final response at the end.
Infer the defensive inner monologue that ran through your mind BEFORE you spoke.
What is the raw emotion or fear behind your defensive walls right now?
Write the thought naturally, as if you are talking to yourself.
You are NOT simply reacting — you are guarding something.

Please ensure the monologue is written entirely from the "I" perspective,
avoiding any clinical detachment or third-person summary.

# Your Context
[Problem Type]: {problem_type}
[Situation]: {situation}
[Your Persona/Background]: {persona_summary}
[Behavior Subtype]: {behavior_subtype}
```

**PROMPT_EVASION（C1-C4, D1-D2）**
```
# Task
The dialogue is COMPLETE — it includes your final response at the end.
You are answering evasively, changing the subject, or giving pseudo-compliance.
Reveal what you are deliberately NOT saying. What thoughts, fears, or resentments
did you consciously suppress when you chose to retreat or evade?
Focus entirely on the HIDDEN subtext beneath the surface interaction.
2-3 sentences max.
```

**PROMPT_VULNERABILITY（CBS5/6，Exploratory）**
```
# Task
You are actively exploring your own emotions or vulnerabilities without resisting.
Show your internal searching process and the heavy, unresolved ambivalence you feel.
This is an emotional stream of consciousness, struggling but open.
```

**PROMPT_SIMPLE_AGREEMENT（CBS2/3/4，Cooperative）**
```
# Task
You are simply accepting the therapist's logic, answering a question, or cooperating.
There is NO hidden agenda, NO deep psychological defense.

CRITICAL: Write EXACTLY 1-2 very short, natural sentences.
Keep it light and strictly surface-level. DO NOT over-analyze.
```

**PROMPT_INSIGHT（CBS7/8，Resolution）**
```
# Task
You have just reached a moment of insight or are making a concrete commitment to change.
Capture the exact cognitive shift, the sense of relief, or the crystallization of
determination that occurred internally just before you spoke.
```

### 8.3 中文模板（RECAP 数据集）

每个英文模板有对应中文版（`_ZH` 后缀），核心差异：
- `"You ARE the patient."` → `"你就是这位来访者。"`
- `"CRITICAL INSTRUCTION"` → `"【关键要求】"`
- 注入字段：`【问题类型】`, `【具体情境】`, `【你的人物背景】`, `【行为子类型】`

### 8.4 评估结论（Prompt 2.0）

- 第一人称沉浸式视角（`You ARE the patient.`）彻底消除"学术分析"口吻
- 平均评分：**3.9 ~ 4.3 / 5.0**
- 极短发言（< 4 词）需跳过，否则诱发幻觉
- 5 个独立模板 > 1 个带条件分支的模板（LLM 混淆风险低）
